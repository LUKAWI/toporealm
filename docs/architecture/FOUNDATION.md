# TopoRealm 基座共识

状态：已确认的架构起点，后续仍需形成实施计划。

## 产品定位

TopoRealm 是包含核心库、CLI、MCP 和 Web UI 的独立产品。它以可扩展图为共同数据模型，通过模块覆盖开发工作流、深度研究、个人学习及其他领域。

现有 Super Plumber 不在原仓库内原地改造。TopoRealm 在独立工作区建立新格式和模块协议，随后通过兼容读取与迁移工具吸收成熟能力。

## 已确认原则

1. 同一张图可以装载多个模块，不采用彼此隔离的产品模式。
2. 对象的主类型负责表达身份；可组合能力负责状态、行为和规则。
3. 模块缺失时，基座仍可无损读取、展示和保存未知模块数据，但暂停相关行为，也不能声称完整校验通过。
4. 雾区属于官方 `exploration` 模块，不属于不可卸载的最小内核。
5. 模块采用声明优先、受信任代码扩展的混合方式。第一阶段只加载本地明确安装的可信模块。
6. Web UI 是基座正式组成部分。模块可以贡献外观、详情面板、编辑表单、图层、操作、统计和推荐列表。
7. 迁移采用原地渐进重构：TopoRealm 内逐步抽取旧项目能力，每一步保持 Super Plumber 的现有开发工作流可用。
8. 基座提供 `toporealm` 与 `toporealm-design` 两个基础 Skills：前者识别图和模块并完成路由，后者只指导通用图结构，不添加具体模块的领域内容。
9. 模块安装决定其 Skill 是否存在；图级启用只决定该 Skill 能否在当前图运行。已安装模块可以继续服务其他启用它的图。

## 最小基座职责

- 图、对象和关系的稳定身份及引用；
- 本地可读持久化和多图管理；
- 结构校验、邻接索引、遍历与子图查询；
- 一致的修改入口、并发写保护、变更记录、快照与恢复；
- 模块发现、版本记录、注册和缺失模块降级；
- CLI、MCP 与 Web UI 的通用接入层；
- 不理解模块私有数据时的无损保留能力。
- `toporealm` 基座路由 Skill；
- `toporealm-design` 通用建图 Skill。

基座不强制任务状态、重试、执行报告、入口、出口、验收终点、无环图或设计审批。

### 基座 Skills

`toporealm` 读取当前图和模块注册表，判断请求应由基座处理还是交给某个模块 Skill。它只负责路由，不代替模块执行领域决策。

`toporealm-design` 指导图的范围、对象身份、能力组合、关系方向、分组、图层和可读性，调用基础校验并通过 Web UI 组织图级审核。它不自行添加任务、研究、学习或探索领域的内容，也不假设整张图必须是 DAG。需要领域判断时，它读取已启用模块的声明并转交对应模块 Skill。

## 模块职责

模块可以声明：

- 主类型、能力与关系类型；
- 私有字段结构和领域校验；
- 生命周期、操作和推荐策略；
- Web UI 渲染、图层、面板和表单；
- CLI/MCP 操作、导出器、skills 和模板；
- 与其他模块的依赖和集成契约。

模块数据使用命名空间。模块未装载时，基座不得猜测其语义或改写其私有数据。

模块可以附带 Skills 和宿主插件适配。模块未安装时不安装对应 Skill；模块已经安装但某张图没有启用时，Skill 保持对其他图可发现，但必须在运行前确认当前图已启用该模块。单张图停用模块不卸载全局 Skill。

## 首批模块

### workflow

承接 Super Plumber 的任务七态、依赖门禁、认领、重试、checkpoint、execution report、验收与下一行动推荐。

### domain-modeling

承接 context、ADR、术语、上下文契约和过期决策传播。

### exploration

承接多个未知区域、开放问题、拆分、解决、重开以及证据关联。关联研究任务完成只触发核对，不自动解决未知。

### research

提供研究问题、来源、论点、证据、冲突、综合结论及研究方向推荐。

### learning

提供知识点、前置关系、掌握记录、练习和基于时间与表现的复习推荐。

## Web UI 边界

基座 Web UI 固定提供画布、布局、缩放、平移、选择、搜索、通用增删改、原始数据查看、模块状态、校验结果、历史、快照、图切换、通用筛选和只读模式。

现有 Super Plumber Web UI 的画布、布局、状态管理、通信和 Markdown 渲染可作为迁移来源。固定的七态颜色、`workflow/domain` 两视图、context hull、工作流前沿和开发专用详情面板应迁入相应模块。

## 格式方向

新格式使用独立版本，例如 `toporealm/v1`。最小对象保留稳定 ID、主类型、标签和模块扩展区；模块私有字段置于各自命名空间。关系的排序、门禁、循环和展示语义由模块注册。

现有 Super Plumber 1.0.0 图通过兼容读取和迁移器进入新格式，不继续向旧 `NodeSchema` 叠加通用化字段。

## 暂不建设

第一阶段不建设远程模块市场、第三方代码沙箱、复杂依赖求解、热更新或完整自适应学习算法。先用 `workflow` 与一个最小 `research` 模块验证协议边界。

## 下一步需要形成的设计

1. 最小持久化格式及无损未知字段规则；
2. 模块清单、注册接口和版本兼容策略；
3. Core、Server、Web、Module SDK 的包边界；
4. Super Plumber 兼容读取及 workflow 模块迁移切片；
5. 最小 research 模块的端到端验证场景。
