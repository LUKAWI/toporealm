# TopoRealm 0.2 Core 重组基线

状态：`l1_baseline` 执行基线，2026-09-14。
适用版本：工作区 `@lukawi/toporealm@0.1.3`。
范围：Core、Module SDK 的基座协议、CLI、MCP、Server、Web、基础 Skills、Codex/Claude/Pi 投影与分发；领域模块只作为只读 fixture，不修改其源码。

## 1. 当前受支持行为

- 图格式保持 `toporealm.graph/v1`，模块格式保持 `toporealm.module/v1`。
- 图事实以工作区 `.toporealm/graphs/<graph-id>/` 下的 YAML 保存，revision、history 和 patch 由当前 `GraphStore` 管理。
- CLI、MCP stdio、HTTP/WebSocket Server 与 Web UI 已提供读图、MutationPlan 写入、undo/redo、模块发现、模块动作和校验。
- WebGraphStore 已有切图与写请求互斥、revision gap 回退全量 snapshot、正常写入应用 fact-level patch 的行为测试。
- 基础 Skills 与 Codex、Claude、Pi 投影可从包生成；包不内置领域模块。

这些是 0.2 重组必须保持的用户级行为。低层 TypeScript interface 按 ADR 0002 迁移到 `ManagedGraph`，不把现有 `GraphStore` 写接口继续视为兼容承诺。

## 2. 生产写入口与迁移归属

| 当前入口 | 当前实现和风险 | 0.2 迁移归属 |
|---|---|---|
| `GraphStore.apply`、`undo`、`redo` | `src/core/store.ts` 直接改写多份 YAML；公共类同时承担读取、候选构造、持久化、历史和锁 | `ManagedGraph` 私有 `GraphCommand` 管线与可恢复提交实现 |
| `applyRegisteredPlan` | `src/module-sdk/registry.ts` 接收可写 GraphStore，模块注册层可触达存储 | Module SDK 只校验声明与计划；Core `ManagedGraph.commit` 独占写入 |
| `ActionExecutor` | `src/module-sdk/actions.ts` 持有 GraphStore 并直接提交 runtime 返回的 MutationPlan | 深化为无存储权限的 ModuleRuntime 调用，由 Workspace Runtime 把计划交给 ManagedGraph |
| CLI `apply`、`undo`、`redo`、模块动作 | `src/cli/index.ts` 自建 store、resolver、activator 和 runtime map | CLI 薄 adapter，统一消费 Workspace Runtime 与 ManagedGraph |
| MCP graph/module mutation tools | `src/mcp/index.ts` 自建 store 和 registry，并拥有另一套 runtime loader | typed MCP adapter 直接消费 Workspace Runtime，不导入 CLI 业务实现 |
| HTTP/WebSocket mutation routes | `src/server/index.ts` 接收 GraphStore，并再次装载 resolver、registry 和 runtimes | Server 消费 Workspace Runtime；patch/event 从唯一 commit 结果产生 |
| Web UI commit/module action | `web-ui/src/lib/store.svelte.ts` 通过 API 写入，客户端维护 switching/writing/revision 状态 | 保留客户端状态机，协议结果扩展 diagnostics、complete 与 notice |

分发安装器对 `.toporealm/modules/` 的写入属于模块安装管理，不是图事实写入；它继续作为独立 interface，但模块启停与图绑定变更必须进入 ManagedGraph 的显式管理命令。

## 4. 重复 Workspace 装配

| 表面 | 当前重复工作 | 统一目标 |
|---|---|---|
| CLI | 解析 active graph、创建 GraphStore、激活 Registry、扫描并动态导入 runtime | 一次调用 Workspace Runtime factory |
| MCP | 保存自己的 graph ID、按调用创建 GraphStore、激活 Registry、再次扫描 runtime | 与 CLI 相同的 factory，MCP 只保留 transport/tool mapping |
| Server | 持有 active GraphStore、列表时创建更多 store、按请求解析模块、第三次装载 runtime | Server session 持有可切换的 Workspace Runtime handle |
| Host projections | 再实例化 WorkspaceModuleResolver 生成模块 Skills | 使用共享的只读工作区发现 service，不获得图写权限 |

删除测试：若删除 CLI、MCP 或 Server 中任一套 resolver/activator/runtime loader，当前其他入口仍能工作，说明这些代码不是各自 interface 的必要深度，应下沉到共享 Workspace Runtime。

## 5. 产品身份漂移

`package.json` 当前版本为 `0.1.3`，但下列受管位置仍保存 `0.1.0`：

- `src/mcp/index.ts` 的 MCP server metadata；
- `src/distribution/hosts.ts` 的 Codex、Claude、Pi manifest、hook 和 npx 命令；
- `tests/host-integrations.test.ts`、`tests/mcp-stdio.test.ts` 的断言或 client metadata；
- `scripts/package-smoke.mjs`、`scripts/registry-smoke.mjs`；
- README 中固定版本的 MCP 示例。

0.2 以一个 Product Identity implementation 派生包名、版本和 channel。模块 fixture 自己的 `0.1.0` 是模块数据，不属于产品身份漂移，不能机械替换。

## 7. 可重复基线命令

在仓库根运行：

```powershell
npm run typecheck
npm test
npm run web:typecheck
npm run web:test
npm run test:package
```

按需单独定位产品表面：

```powershell
npx vitest run tests/core-store.test.ts tests/core-contract.test.ts
npx vitest run tests/cli.test.ts tests/mcp-stdio.test.ts
npx vitest run tests/web-product.test.ts tests/browser-smoke.test.ts
npx vitest run tests/base-skills.test.ts tests/host-integrations.test.ts
```

执行 `npm test` 会先运行项目 `pretest` 构建。浏览器 smoke 依赖本机 Chromium；缺少浏览器时应明确记录环境限制，不能把普通组件测试冒充浏览器验收。

2026-09-14 实测基线：

- `npm run typecheck`：通过；
- `npm test`：15 个测试文件、38 项测试通过，包含真实浏览器协议、MCP stdio、Server 打包资源和模块生态场景；
- `npm run web:typecheck`：0 error、0 warning；
- `npm run web:test`：11 个测试文件、44 项测试通过；
- `npm run test:package`：干净安装通过，报告 `@lukawi/toporealm@0.1.3`、87 个包入口检查项以及 CLI help、serve、MCP 均可运行。
