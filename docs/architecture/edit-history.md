# TopoRealm 编辑历史与并发契约

状态：核心边界已确认。

## 基础编辑能力

Core 必须支持对象、关系和图级元数据的创建、修改、删除、撤销与重做。Web UI、CLI、MCP 和模块动作共用同一个写入入口；模块返回的图内 `MutationPlan` 也必须进入同一历史。

一次用户动作或一次成功的 `MutationPlan` 是一个撤销单位。它包含恢复所需的变更前后值；同时创建、修改或删除多个对象与关系时，撤销和重做必须整体完成。

## 持久化线性历史

每张图维护持久化的线性编辑历史和当前位置，后端或 Web UI 重启后仍可继续撤销与重做。撤销后发生新编辑时，旧 redo 分支不再可达；首版不提供分支历史、历史合并或时间线树。

YAML 对象和关系仍是当前事实来源。历史用于恢复编辑与审计，不要求通过重放全部事件才能读取当前图。

## 删除与恢复

删除成功后，对象或关系文件从事实目录移除，历史记录保留恢复所需的完整值。删除对象时，与其关联且由本次操作删除的关系进入同一撤销单位。首版不在事实目录保留 tombstone 文件。

## 撤销边界

- Core 管理的图内创建、修改和删除必须可撤销与重做；
- `artifact` 与 `external` 副作用不承诺由通用撤销恢复；
- 用户直接修改 YAML 视为外部编辑，Core 重新读取当前事实并使旧 redo 路径失效，不尝试推断逆操作；
- 单次写入始终原子完成，失败不产生半份历史或半份图状态。

## 并发与 revision

每张图只有一个单调递增的 revision。Core 使用图级写锁串行提交变更；携带过期 revision 的 Web、CLI、MCP 或模块动作被拒绝，并返回当前 revision 供调用方重新读取。首版不自动合并并发写入。

成功的普通编辑、撤销和重做都会产生新 revision 及相应增量 patch。索引和 WebSocket 消息都从已提交的 Core 变更生成，不从派生文件变化猜测业务事件。
