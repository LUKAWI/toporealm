# TopoRealm Skills 与宿主插件契约

状态：基座 Skills、模块 Skill 粒度、安装生命周期与三宿主发行结构已确认。

## 目标

Skills 教 agent 如何使用 TopoRealm 与已安装模块。Schema、操作输入和适用动作仍由模块清单、注册快照和 MCP 提供，Skill 不复制机器契约。

模块安装决定其 Skills 是否存在于宿主环境；图级启用只决定这些 Skills 能否作用于当前图。关闭一张图中的模块，不会卸载该模块，也不影响其他图使用其 Skills。

## 基座 Skills

TopoRealm 基座固定提供三个 Skills：

### `toporealm`

读取当前工作区、目标图和模块状态，判断请求由通用 Core 处理还是转交某个模块 Skill。它不执行模块领域决策。

### `toporealm-design`

指导通用图的范围、对象身份、关系方向、能力组合、布局和可读性，并组织 Web UI 图级审核。它不预设任务、研究或学习内容，也不要求图是 DAG。

### `toporealm-join`

以只读方式读取图的范围、已启用模块、主要对象、近期变化和当前关注区域，再将后续工作路由给适用模块。它不改变状态、不认领对象，也不启动模块执行。

## 模块 Skill 粒度

每个模块默认只有一个以模块命名空间为边界的主 Skill。只有同时满足以下目的之一时才增加附加 Skill：

- 具有与主 Skill 明确不同的触发条件；
- 对应独立工作阶段；
- 必须与执行者隔离的纪律或复核职责。

普通查询、创建、更新、删除和推荐操作不拆成 Skill，由 MCP 的动作发现和统一执行入口提供。Skill 只说明 agent 的工作方法、判断边界和停止条件，不重复保存字段 Schema、完整参数表、操作列表或模块版本信息。

例如 workflow 模块可以保留一个领域入口，并为执行、独立复核和 TDD 提供确有独立触发边界的附加 Skills；更新状态、读取下一行动等普通操作不各自形成 Skill。

模块清单继续使用已有的单一 Skills 索引：

```yaml
skills:
  directory: skills/
```

基座从目录中读取一个主 Skill 和可选附加 Skills，不为每个 Skill 在 `module.yaml` 增加重复配置。每个 Skill 自身声明名称、简短描述和触发边界。

## 图级适用检查

模块 Skill 开始工作前，通过固定 Core 或 MCP 接口确认：

1. 当前目标是否是一张可读的 TopoRealm 图；
2. 所属模块是否已安装且可用；
3. 目标图是否显式启用该模块；
4. 所需能力是否存在于当前注册快照。

检查失败时返回模块状态和恢复方向，不尝试猜测缺失模块语义。这个检查由基座提供统一调用，模块 Skill 不各自实现一套绑定解析。

## 三套宿主投影

TopoRealm 正式维护 Codex、Claude 和 Pi 三套可直接导入的完整投影，而不是要求三个宿主读取同一份中立目录：

```text
integrations/
├─ src/                 # 共享规范源、模板和宿主差异源
├─ codex/               # 可直接导入的 Codex 插件
├─ claude/              # 可直接导入的 Claude 插件
└─ pi/                  # 可直接导入的 Pi 扩展
```

三个发布投影分别维护宿主所需的真实文件，包括：

- Codex 的 `.codex-plugin/plugin.json`、marketplace 条目、Skills、MCP 配置和 hooks；
- Claude 的 `.claude-plugin/plugin.json`、marketplace 条目、Skills、MCP 配置和 hooks；
- Pi 的 `index.js`、Skills、扩展注册与其支持的生命周期接入。

共享规则只在 `integrations/src/` 保留一份规范源；构建器按宿主条件模板生成三套完整正文。路径、入口、调用方式、清单字段和生命周期事件可以因宿主而不同，不能为了文本一致而牺牲可直接导入性。三套生成产物都进入发布校验，禁止把其中一套当作其他宿主的隐式兼容层。

基座的固定 TopoRealm MCP 连接进入三套宿主投影。模块仍只贡献自身的 Skills 和模块资产，不另起 MCP Server；模块 Skills 由安装流程加入三套投影能够发现的位置。

## 投影范围与生命周期

模块绑定范围直接决定宿主投影范围：

- 全局安装模块的 Skills 进入宿主用户级发现目录；
- `workspace` 和 `path` 模块的 Skills 进入当前项目的宿主发现目录。

`.toporealm/modules.yaml` 是项目投影的期望状态，不增加另一份需要用户维护的投影配置。宿主适配器通过统一的 `host sync` 读取模块绑定并协调对应目录；宿主缺少原生项目级 Skill 目录时，由其适配器生成等价的项目入口。

每个生成目录包含一个轻量所有权标记，记录模块身份、版本、来源和生成器身份。安装与更新只创建或替换 TopoRealm 所有的投影；卸载只删除所有权完全匹配的目录，不删除、合并或覆盖用户手写 Skills。全局投影的期望状态来自全局模块安装记录，项目投影的期望状态来自工作区绑定。

npm 只用于获取模块 tarball。`toporealm module add` 校验并把模块解包到用户级或工作区 `modules/` 目录，然后更新绑定并调用同一套 `host sync`；安装后的模块不依赖 `node_modules`。npm 模块与用户手写模块具有相同的 Skills 投影能力，区别仅在于受管模块带有可供更新和卸载使用的来源记录。

## 首版基座钩子

现有 Super Plumber 包含 `session-brief.mjs` 和 `git-guardrails.mjs` 两个可选脚本，但没有在 Codex、Claude 或 Pi 的发行清单中注册，因此没有形成插件默认行为。

TopoRealm 正式使用宿主钩子改善图入场和上下文恢复。钩子属于宿主适配层：每个宿主映射自己支持的会话启动、恢复和压缩恢复事件，核心模块协议不假设三个宿主拥有完全相同的事件名称或能力。

首版只有一个只读行为：读取当前工作区并输出短图入场摘要。摘要包含目标图、已启用或缺失模块、注册快照修订号和适用 Skills，并使用内部固定长度上限，不增加用户配置参数。

钩子不能修改图、认领或执行领域对象、复制 Core 门禁、动态注册 MCP 工具，或绕过动作接口。首版不注册 `PreToolUse` 拦截、`Stop` 检查和 git 护栏，模块也不能贡献宿主钩子。宿主缺少相应生命周期时，首次调用 `toporealm` Skill 完成同一入场读取。
