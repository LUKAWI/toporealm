# ADR-0005: 双层模块与最小执法

状态：已接受（2026-09，重建 grilling 会话 D8/D9/D10/D11/D12）

## 背景

0.x 模块协议是"声明式为纲 + fail-closed 执法"：module.yaml 声明七类贡献，core 聚合 schema 校验、validator（缺/抛/返回非结构化均 fail-closed）、私有区守卫、STALE_ACTION 等。20 道写路径门禁中约 18 道针对模块。约 60 个稳定错误码中约 35 个为模块治理而设。而模块 runtime 本身是 in-process Node 代码——"只能返回 MutationPlan"从来只是 API 纪律而非安全边界。

## 决策

**模块 = 双层。**

- **声明层**（module.yaml）：身份（id/namespace/version）、依赖声明（requires.modules，装载期检查）、主类型词汇表、静态 UI 投影（颜色/图标）、entry 入口。角色是协调契约（注册、发现、防冲突），**不是执法依据**。
- **代码层**（runtime，in-process 加载）：`activate(api)` 时注册命令（含全部元数据）、校验钩子、表单；拥有全权 API（读图、提交、订阅事件）。信任在安装时刻完成（npm install 本来就是代码执行）。

**执法只剩一条所有权法**：一个模块的提交只能触碰自己命名空间下的主类型或无主/公共主类型。它是模块互信的协调边界（防手滑），不是安全边界；"模块缺失时其数据冻结"退化为同一规则的退化情形。

**领域校验 = 钩子制**：模块订阅 before-commit 事件，可附诊断、可否决；core 不聚合、不 fail-closed。悬空关系检查（~5 行）作为 commit 内置引用完整性保留。

**组合规则**：模块互操作唯一正道是图数据面（跨 namespace 建关系、读对方实体）；模块集在 daemon 启动时冻结，改模块 = 重启；registry snapshot / STALE_ACTION / 激活重算整类问题不复存在。

**贡献分层**：manifest 瘦身为上列五项；一切行为（命令、钩子、表单）在代码注册时声明，由 daemon 自省提供目录。术语：动作（Action）→ **命令（Command）**。

**打包**：npm 包 + 本地路径两种安装源；禁 install 脚本保留（安装期信任的唯一执法点）；允许捆绑 node_modules 依赖。

## 后果

- 20 道门禁 → 2 条；~60 错误码 → 预计 <15；validation-types/validation/fail-closed/JSON Schema 编译整套退役。
- 模块钩子理论上可否决全图写入（砖化风险）：这是模块与用户的契约，daemon 明示"被 X 否决"，卸载即恢复。
- in-process 全权代码意味着恶意模块在运行时无解——平台以安装渠道纪律（禁 install 脚本、所有权标记）与用户教育承担。
