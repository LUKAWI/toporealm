# ADR-0007: 作用域模型——装了就生效，项目遮蔽全局

状态：已接受（2026-09-26，1.1.0 规划 grilling 会话 D27；对抗评审后采纳）

## 背景

1.0 的模块作用域是「工作区绑定显式列表」：`modules.yaml` 写绑定、daemon 按绑定全量装载、
graph.yaml 的 modules 列表仅作记录（实现层面「图级启用」从未真正按图过滤）。绑定 schema
预留的 `global` 来源只是占位（装载时跳过+warning），没有全局池。用户痛点：装模块必须先建图、
模块注册不分层、每装一个模块都要逐项目重复。

作用域模型有两个候选：全局池作为「仓库」（装了不等于启用，项目显式绑定才生效）或全局池作为
「启用面」（装了就所有项目生效）。前者与 1.0 术语「图级启用」的分层一致，后者更符合直觉。

## 决策

- **模块集 = 全局池 ∪ 项目池 ∪ path 绑定，装了就生效，无第三步启用动作**；「图级启用」概念废除。
- 全局目录 `~/.toporealm/`（`TOPOREALM_HOME` 可覆盖）：全局模块池，目录即注册。
- 项目装同 id 模块**遮蔽**全局（就近优先）；不做项目级排除，命名空间冲突靠现有执法大声报错。
- `modules.yaml` 收缩为 `source: path` 绑定的唯一载体（模块作者开发期工作流与测试接缝）。
- graph.yaml 删除 `modules` 字段，清单升 `toporealm.graph/v3`；1.0 图无自动迁移（破坏性变更，D25）。
- 模块集 digest = sha256(遮蔽解析后的有效集 `pool:id@version`)；requires.modules 跨池联合解析；
  global 池坏模块跳过+warning，项目池坏模块大声失败。

## 理由

- 1.0 的装载实现本就是 root 级全量装载——「装了就生效」与实现的距离最小，是撤销一层显式协调而非新建机制。
- 全局启用模型被选中的代价（作用域不可预期、排查多一层）由「`module list` 分段显示 + 遮蔽标注 + digest 精确失效」消化。
- 不做排除机制：命名空间唯一性执法已把真实冲突拦为大声失败；少一个概念，模块集是启动冻结的，后续可加不破契约。

## 后果

- CONTEXT.md 术语：「图级启用」废除，新增「作用域」「全局池」；模块绑定语义收窄为 path 链接。
- 双层工作区布局变更（`.toporealm/graphs/`、`TOPOREALM_HOME`）由蓝图 §1.8 D26 承载。
- v3 图格式与 v2 不兼容；1.0 图的唯一转换路径是 dogfood 自举的一次性手工步骤。
