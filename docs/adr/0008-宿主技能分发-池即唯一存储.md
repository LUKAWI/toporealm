# ADR-0008: 宿主技能分发——池即唯一存储，原生通道读取

状态：已接受（2026-09-26，1.1.0 规划 grilling 会话 D28；对抗评审后采纳）

## 背景

1.0 的模块技能经 `host sync` 投影：扫描已装模块的 `skills/`，按宿主格式生成投影文件
（claude-code 自包含 plugin 目录——但从未接入 Claude Code 的发现体系，`plugin add` 搜不到；
pi 落项目级 `.pi/` 原生发现位）。投影机制带来所有权标记、重同步、冲突跳过一整套机器，且
「模块升级后需重同步才生效」存在陈旧态问题。

1.1.0 规划中评审过三个方案：A) 池即事实源、投影到宿主原生发现位（`~/.claude/skills/` 等）；
B) 发布物双栖自分发（模块包自带 pi 字段与 claude 插件声明，toporealm 安装时联动）；
C) 混合。用户否决了「往宿主自有目录写文件」与「双源漂移」，实测确认 claude 对 skills 的
扫描是严格一层（池内深层嵌套与 skills 目录内多层嵌套均不可见），pi 扩展 API 存在
`resources_discover` 动态贡献 skillPaths 的能力。

## 决策

- **模块技能文件只存在于池中**（全局 `~/.toporealm/modules/<id>/skills/`、项目
  `.toporealm/modules/<id>/skills/`），零拷贝、零投影再生；toporealm 不写任何宿主自有目录。
- **claude code**：基座 marketplace 插件（纯静态：基座 CLI 技能 + SessionStart 钩子）。
  钩子运行 `toporealm skills index`，把「技能名 · 所属模块 · 描述 · 绝对路径」索引注入
  会话上下文，agent 按需 Read 全文（复刻渐进披露两阶段）；索引按当前工作区解析链生成，
  项目模块技能只在本项目会话出现。
- **pi**：主聚合包加 `pi` 字段（`pi install npm:@lukawi/toporealm`），内置扩展订阅
  `resources_discover` 返回池内 skills 目录作为 `skillPaths`，pi 原生发现注册。
- **`host sync` 动词与整套投影机器删除**；模块作者义务收缩为按 Agent Skills 标准带
  `skills/` 目录。
- `skills index` 硬约束：纯文件层绝不拉起 daemon；坏清单跳过；跨模块重名并列输出靠模块列
  消歧；无工作区空输出 exit 0；钩子命令兜底静默。

## 理由

- 「装了就生效」一条哲学贯穿模块能力与技能：技能版本 = 池中版本，天然锁步，消灭重同步陈旧态。
- 模块作者负担最小（一个标准目录），双宿主同时生效；基座不碰宿主自有目录，边界干净。
- claude 侧钩子索引是实测约束下的最优解：原生发现被证明不可达（一层扫描），插件纯静态化
  避免了「本地 marketplace 就地再生内容」的机器；pi 侧原生注册无任何妥协。

## 后果

- `host sync` 从 CLI 动词面删除，`packages/distribution` 的投影代码（hosts.ts）移除；
  1.0 投影残留（`.pi/skills/`、`.toporealm/hosts/`、`.toporealm-sync.json`）给手工清理说明。
- claude 侧模块技能不是原生注册技能（无 `/skill:` 命令面），可达性依赖钩子索引注入——
  索引质量（描述提取、容错）成为体验关键。
- 将来若 claude 提供动态技能贡献机制，钩子索引可平滑替换（插件内容纯静态，改动面小）。
