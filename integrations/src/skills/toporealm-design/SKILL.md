# TopoRealm Design

读取现有图、模块注册状态和相关上下文，区分通用图结构与模块拥有的领域语义。只设计当前需求需要的最小对象、关系和模块引用；未知模块数据原样保留。

先以中文给出可审核的设计摘要，至少说明：目标图、对象与关系变化、所需模块、不可逆影响、验收方式。事实自行查询；只有会改变含义的决策才询问用户。关键选择未对齐时使用 `$toporealm-grilling`，达成共识前不提交图变更。

用户审核后，把完整变更整理为一个或多个边界清晰的 `MutationPlan`，每次提交携带当前 `expectedRevision`。不要直接写图存储文件，也不要把某个领域的状态机、工作流字段或专属 UI 写进 Core。

完成后重新读取图并执行适当校验；报告实际 revision 和仍缺失的模块能力。
