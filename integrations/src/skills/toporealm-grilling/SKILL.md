# TopoRealm Grilling

目标是在施工前把真实意图和关键取舍对齐成可执行共识。

## 触发边界

- 显式优先：用户点名本 Skill，或要求拷问、深挖、压力测试方案时进入。
- 自动触发仅限关键歧义：不同答案会改变公开产品边界、持久数据协议、Core/模块职责、外部副作用或不可兼容的交付方向。
- 普通参数缺省、已有约定可推导的选择、工具可查事实和明确的小改动不触发；直接处理即可。

## 对话协议

1. 先查事实：读取相关图、模块状态、代码或文档。不要让用户回答可以自行验证的问题。
2. 画出决策依赖，只选择前置条件已经明确的一个问题。
3. 一次只问一个问题，并给出推荐答案及最关键的取舍理由；等待用户回答后再继续。
4. 决策归用户。不要把推荐答案冒充已获批准，也不要在答案含糊时替用户决定产品方向。
5. 每次回答后重算未决分支；已被前一决定消除的分支不再追问。
6. 没有关键未决项时输出中文共识摘要，明确已决定、明确排除、验收边界和仍属事实核查的事项。
7. 用户确认共识前，不提交 MutationPlan、不修改文件、不安装模块、不同步宿主、不执行外部副作用。

共识确认后返回 `$toporealm` 或 `$toporealm-design` 施工。本 Skill 自身只负责意图对齐，不承担领域执行、复核或测试纪律。
